# Mini LM

ブラウザで `index.html` を開くだけで使う、ローカルテキスト専用の簡易 NotebookLM 風ツールです。Groq Chat Completions API を使って回答します。

## 使い方

1. `index.html` をブラウザで開く
2. Groq API Key を入力する
3. `sourceフォルダを選択` で `source/` を読み込む
4. ファイル一覧で回答対象にする文書にチェックを入れる
5. 質問する

読み込み対象は `source/` 内の `.txt`, `.md`, `.markdown`, `.csv`, `.tsv`, `.json`, `.log`, `.text` です。対応ブラウザでは、選択した `source/` フォルダをブラウザ内に保存します。次回以降は権限が残っていれば自動読込し、権限確認が必要な場合は `保存済みsourceを再読込` を押してください。

ブラウザがフォルダ保存に対応していない場合は、毎回 `source/` フォルダを選択してください。

ファイル一覧のチェックを外すと、その文書は読み込まれたまま回答対象から外れます。大きな文書を試すときは、1ファイルだけチェックしてから質問できます。

## 巨大テキストへの対応

- 規程・条文系の見出しを検出し、できるだけ条文や見出し単位でチャンク化します。
- ファイル全体を通常質問のたびにAPIへ送らず、ブラウザ内でチャンク化して索引を作ります。
- 通常検索では、質問に関連するチャンクからさらに質問語周辺を抜粋してGroqへ送ります。
- GroqのTPM上限に当たった場合は、根拠量を減らして自動で1回リトライします。
- 見落としを減らしたい場合は `高精度網羅（全チャンク確認）` をオンにしてください。全チャンクを小分けで確認し、関連情報の抽出、近傍再確認、抽出メモ統合、最終回答監査を行います。
- `網羅API間隔(ms)` を大きくすると回答は遅くなりますが、Groqのレート制限に当たりにくくなります。429が返った場合、短い待機だけ自動リトライします。長い待機が必要な場合は粘らず停止し、対処方法を表示します。
- 処理中は画面下部に進行状況が出ます。待機中・送信中・リトライ中は継続中として表示し、最終的に失敗した場合はチャットに停止理由を残します。

## 注意

API Key をブラウザで扱うため、公開サイトには置かないでください。自分のローカル環境だけで使う前提です。
